# Correctness review after 1.1.0

Reviewed from `5b951ec965c6e5d3a1fe73b1c9bc52c1468085b0` (the merge of 1.1.0 into main). The earlier local checkout was behind GitHub; findings were rechecked after fetching current main. Review and tests used an isolated checkout, generated audio and disposable profiles. The existing checkout, running personal app and personal library were preserved.

## Fixed behavior and evidence

| Area | Failure and correction | Regression evidence |
| --- | --- | --- |
| Exclusive output | A stream opened for a 16-bit song could keep truncating later 24-bit songs at the same rate. Streams now use the widest supported layout at their rate, carrying lower precision samples exactly. Explicit loads also recompute pending rate changes, preventing stale pending state from silencing a replacement track. | Synthetic PCM transition and pending-rate tests; no physical DAC claim. |
| Playback transitions | Disabling crossfade or enabling end-of-song sleep could retain an already trimmed next-song intro. Those changes now rebuild the preload. A failed repeat preload now stops at EOF instead of waiting forever. Positive-to-positive crossfade changes retain already mixed progress. | Deck/preload state regressions, including failed repeat before EOF. |
| Equalizer | Bypassed filters passed NaN/infinite samples through; finite double-precision filter results could overflow when converted to float. Invalid output now becomes silence and resets only the affected channel. | Bypass, overflow and opposite-channel continuity tests. |
| Library moves | Deleting one of two already indexed copies could merge its favorite, history and playlist references into the survivor. Two missing copies could also collapse into one new destination. Relinking now requires a newly indexed destination and a unique source. | Both generated-WAV cases failed before the fix and pass afterward; ordinary unique moves still pass. |
| Playlist and queue selection | Moving playlist rows left old positional selections active. Failed or unchanged queue moves could preserve picks through a later unrelated edit. Hidden queue entries also offset the selected moved row. Selections now clear when playlist entries change, and queue moves track their expected result using full queue positions. | Five browser cases failed against baseline and pass after the fix, including the lossless filter case below; three queue-selection unit tests. |
| Lossless filter | ALAC files were excluded despite the app recognizing their codec. Filtering now uses the existing audio-quality classification, retaining ALAC and excluding AAC. | Synthetic browser test. |
| Lyrics | Paused seeks and pause/resume transitions used stale clocks; footer LRC offsets affected no earlier lines; incomplete timestamps were treated as synced text and disappeared; empty LRCLIB results hid usable alternatives. These now update immediately, apply file-wide offsets, retain plain text and choose usable results. Removing a pending track also clears its loading state. | Failing parser, Rust selection and browser timing cases reproduced before fixes; all now pass. |
| Spotify collections | Updates skipped changed candidate matches, artist credits and durations; absent revisions could trigger needless saves. Duplicate Spotify entries shared one confirmation/rejection decision. Comparison now uses the actual compact saved representation, and each repeated occurrence preserves its own decision. | Four frontend failures reproduced before fixes; targeted and full suites pass. |
| Spotify sign-in | A late refresh could recreate a disconnected session or overwrite a newer connection; simultaneous refreshes could race over a rotating token and temporary file. Per-profile generation/file guards and refresh serialization prevent these outcomes without blocking Disconnect during network waits. A canceled reconnect preserves an existing in-flight token rotation. | Five auth regressions, using synthetic encrypted Windows credentials and controlled request timing. |
| Last.fm | Disconnect/Remove/newer setup during initial token or key validation could be undone by a late result. Attempts now register before network waits and check cancellation before opening the browser, writing credentials or setting poller errors. Malformed or partial scrobble acknowledgements no longer clear queued listens; non-success HTTP responses cannot imply success. | Injected cancellation/setup tests plus complete/malformed acknowledgement cases. Acknowledgement handling follows the [Last.fm response schema](https://www.last.fm/api/show/track.scrobble). |
| MusicBrainz pacing | Reading elapsed time twice around a subtraction could underflow after a scheduling delay and poison the shared pacing lock. Remaining delay now uses a single saturating subtraction. | Source-level timing analysis; formatting and Rust checks. |

The first native runs used a QA window restored at roughly 800x600, below the app's supported minimum. Settings was covered by the player bar there (27/28 scenarios passed). Explicitly sizing the QA window to the supported dimensions resolved that harness condition; the final complete run passed 28/28. The QA instance was then closed; the existing personal instance remained running.

Run browser regressions with `npm run test:browser`. They use installed Microsoft Edge by default; set `SLATE_BROWSER_CHANNEL` to another installed Playwright channel if needed. They create synthetic in-memory state and start ephemeral loopback Vite servers; they do not operate the native app or personal data.

## Limits and tradeoffs

- Physical DAC format acceptance, sample-rate switching and unplug/replug recovery were not exercised. Exclusive PCM/state tests do not establish hardware behavior. Native playback used generated silent fixtures on shared output.
- Live Spotify, Last.fm, LRCLIB and MusicBrainz account/service behavior was not revalidated. Authentication tests use disposable synthetic credentials; no public listening activity was sent.
- The personal-library decode test and manual taskbar glyph export remain unrun. The two generated codec/FLAC tests were explicitly run in addition to the default Rust suite.
- Move detection is deliberately conservative: an already indexed destination from an earlier scan is not assumed to represent a move. Ambiguous copies retain independent state instead of being silently merged.
- Repeated Spotify occurrences are matched by occurrence order because the source supplies no stable per-occurrence identity.
- No installer signing, release packaging, deployment, merge or push was performed. This review does not establish that the entire repository is bug-free.
