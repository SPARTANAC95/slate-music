# Architecture

## Boundaries

React renders real state obtained through narrowly scoped Tauri commands. Rust owns indexing, SQLite, playback, credential encryption and Spotify requests. No music file write operation is exposed. Artwork uses a custom protocol that accepts a hexadecimal cache key rather than arbitrary paths. The content security policy disallows remote scripts and embedded pages.

`src/App.tsx` owns navigation and session presentation; `components.tsx` contains shared accessible controls and virtualized rows. `library.ts` groups metadata and describes quality; `listTools.ts` sorts lists and tracks picked rows; `dnd.ts` handles drag and drop; `search.ts` ranks typo-tolerant matches for search and the command bar (`CommandPalette.tsx`). `NowPlaying.tsx` shows the cover, synced lyrics (`lrc.ts`) and the signal path; `artColor.ts` picks the accent from a cover. `smart.ts` evaluates smart playlists (`SmartPlaylistEditor.tsx`); `insights.ts` computes Home shelves and Your year (`YourYear.tsx`). `matching.ts` and `spotifySources.ts` implement conservative Spotify matching and automatic updates. `ImportPanel.tsx`, `SettingsPanel.tsx`, `SoundSettings.tsx`, `SharingSettings.tsx` and `updater.ts` own their respective flows.

`src-tauri/src/lib.rs` wires native commands and windows; commands that touch the disk, decryption or the network run on background threads. `db.rs` owns the SQLite schema and migrations. `library.rs` scans and watches directories on worker threads, uses Lofty to read tags, recognizes moved files, and caches resized artwork by content hash. `audio.rs` owns the mixer, the output (shared through Rodio, or exclusive through `wasapi.rs` with format choices in `exclusive.rs`) and serializes queue mutations; `dsp.rs` is the equalizer and `loudness.rs` measures songs for levelling and smart crossfades. `lyrics.rs`, `years.rs` and `artists.rs` find lyrics, original years and artist photos (online only when enabled; MusicBrainz requests share one pace). `scrobble.rs` (Last.fm) and `discord.rs` share listening when switched on. `taskbar.rs` and `desktop.rs` own the taskbar buttons, tray and window identity. `spotify.rs` implements PKCE, loopback authorization, DPAPI token storage, refresh, the playlist list and paginated playlist retrieval (the 2026 `/playlists/{id}/items` API).

## Indexing and data

Files are identified by their absolute path. Modification time and size avoid reading unchanged tags. Folder removal only marks retained entries unavailable. A file moved inside the library is matched to its unavailable copy (same size, tags and length) and inherits its favorite, plays, history and playlist places; ambiguous copies and songs on disconnected drives are left alone. Album grouping uses album title and album artist (falling back to track artist). Disc and track numbers order multidisc albums. Possible duplicates are shown conservatively rather than deleted.

The scan accumulates results away from the rendering thread and commits to SQLite. Filesystem events trigger debounced incremental scans. Errors remain visible in Settings. Very large libraries have virtualized song rows; the metadata catalog is currently loaded into memory, so libraries with hundreds of thousands of entries have not been benchmarked. A cover image added beside songs later is picked up on the next scan.

SQLite WAL with full synchronization stores a migration version, tracks, application state and collections. Playback state is saved periodically and during native shutdown. History keeps the newest 100,000 plays. Restoration explicitly pauses audio. Data survives replacing the application binaries.

## Audio

`lrc.ts` parses standard and Enhanced LRC (`parseLrc`) and lays the result out for display (`showLyrics`): every sung line gets a start and an end for each word. Explicit Enhanced LRC `<mm:ss.xx>` boundaries are kept exactly (a source segment may be a word, a syllable or a phrase); a line with only a line time stamp, ambiguous repeated stamps included, has its words spread between its own start and the next line by their length, capped so a line is not stretched across a pause, and is marked `estimated`. Empty lines and a late first line become pause rows. File-wide offsets apply equally to lines and words; plain text stays untimed.

`LyricsPanel.tsx` renders the rows once with React and then draws every frame straight to the page: a small `Stage` object sets which row is active, each word's `--p` (0 to 1, which CSS turns into a left-to-right fill with no transition of its own) and the scroll position. No React state changes per frame, so the rest of the app is not redrawn. `VolumeControl.tsx` is shared by the main and Now Playing views and uses the same native volume command.

`playbackClock.ts` turns the engine's snapshots (about every 240 ms, in steps the size of the sound card's buffer) into a steady clock. Each snapshot carries `at`, the time its position was read, so the time it spent on its way is added back; between snapshots the clock keeps running and leans towards them by running up to 6% fast or slow, jumping only when a snapshot is more than 180 ms away (a seek or another song). It stops when the engine reports `clockRunning` false (paused, or waiting for a deck or an output-rate change; recomputed, never restored from a session), when two snapshots report the same position, and after one second without any. `isStale` lets the app drop a snapshot read before the one already shown. Lyrics are then placed at the clock's position minus `outputLatency` (what Windows reports for the open stream plus the engine's own buffer: `wasapi.rs`), minus the per-device delay and plus the per-song adjustment kept by `lyricTiming.ts` in WebView storage. Windows does not report the delay of every Bluetooth device, which is what the per-device setting is for. A source's own LRC offset still applies.

Each deck streams a decoder through a stereo format adapter. In shared mode everything is mixed at 48 kHz and played through Windows; in exclusive mode each song is sent at its own sample rate (or the nearest the device takes) as whole-number samples, and a change of rate reopens the device between songs. A worker preloads the next deck so the mixer crosses boundaries without reopening the stream. Crossfades blend the tail and head; smart crossfades use measured silence at song edges and never fade songs that continue an album. Levelling and the equalizer apply in the mixer; with both off and volume at 100%, exclusive output is bit-perfect, which the signal path reports.

The mixer counts output samples itself, so a song loaded or sought between a left and a right sample waits for the next left one and channels never swap. A song that ends while the next is still being prepared waits silently instead of stopping. About once a second the engine follows Windows' default device (or returns to a chosen device that reappears) and replaces a shared output that stopped asking for samples; output errors pause playback and trigger reconnection.

Sample continuity is measured for contiguous 48 kHz FLAC fixtures. Gapless decoding is not promised for every unusual encoder/container combination; surround files are folded down to stereo. SMTC carries track metadata and playback actions; the mini-player shares the same native engine.

## Updates and trust

Only HTTPS production endpoints are configured. Tauri checks the signed artifact and its signed version against the embedded public key. No private signing key ships in the app. A debug-only verification command permits loopback fixture URLs; release builds reject that command and never enable insecure updater transport. Downloading does not install. The UI gates installation while playing and requires user action.

Spotify credentials never enter the renderer. OAuth uses a random state and PKCE challenge, binds a loopback listener, and expires after a bounded wait. Playlist pagination is restricted to the expected Spotify API path and checks the retrieved total. Import results contain metadata and local track IDs, not audio.
